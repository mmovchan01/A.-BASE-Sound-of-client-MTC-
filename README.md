# Голос клиента — классификация эмоций MTC

Вход: 2048-мерный эмбеддинг. Выход: `angry`, `neutral`, `positive`, `sad`.
Решение: стандартизация признаков, компактный MLP, усреднение вероятностей
двух моделей с разными производными seed и настройка смещений классов под macro-F1.

## Установка

Python 3.12, CPU; GPU не требуется. Для экономии диска устанавливайте CPU PyTorch:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install numpy==2.4.6
pip install torch==2.14.1 --index-url https://download.pytorch.org/whl/cpu
```

`requirements.txt` фиксирует основные зависимости. Полное окружение обучения
сохраняется в `reports/final/environment.txt`.

## Данные

`train.npz` хранится в Git LFS. После клонирования нужен `git lfs pull`.
135-байтовый текстовый указатель LFS — **не** обучающая выборка.
Настоящий архив занимает 1 000 558 195 байт. Данные в репозитории:

| Класс | Число обучающих примеров |
|---|---:|
| angry | 44 000 |
| neutral | 21 500 |
| positive | 44 000 |

Всего 131 000 строк; public test — 6 600. Оба блока по 1024 признака

не найдено. Это не исключает похожих реплик или общих дикторов; ID дикторов нет.

## Воспроизведение

```bash
python train.py --data train.npz --config final_config.json \
  --seed 269860790 --out models/reproduced --threads 4
python predict.py --weights models/reproduced --test public_test.npz \
  --out submission_seed_269860790.npz
```

`train.py` обучает только финальный ансамбль, без перебора гипотез. Каталог вывода
должен быть пустым. Без `--seed` генерируется новый случайный seed, который
записывается в `meta.json`. Для воспроизведения передавайте указанный выше seed.
Участники ансамбля используют seed + 1000 × номер участника. Фиксируются Python,
NumPy и PyTorch, включены детерминированные алгоритмы. Для побитового совпадения
нужно одинаковое окружение и CPU/число потоков; между платформами возможны различия.

`predict.py` только считывает веса: обучение и подбор параметров не запускаются.
NPZ содержит исходные тестовые `embeddings` и строковые `targets` формы `(N,)`,
типа `<U8`, как в образце. Порядок строк сохраняется.

## Валидация и ограничения

Гипотезы сравниваются на фиксированном стратифицированном 90/10 split.
Финальный ансамбль обучается на 95% train; оставшиеся 5% используются для выбора
checkpoint и настройки смещений классов. Стандартизатор обучается только на
обучающей части. Калиброванный F1 на этой же выборке оптимистичен: это не
независимая оценка. Public/closed test labels отсутствуют, конкурсный F1 неизвестен.
Для более строгой оценки нужны отдельный неизменяемый holdout или nested CV.

Разведочные эксперименты: `reports/dev_sweep.json` (подвыборка 16 000 с uint8
квантизацией, не сравнивать напрямую с полными данными). Сравнивались размеры MLP,
линейный классификатор и способы нормализации. Полные эксперименты и финальный
отчёт находятся в `reports/final/`. Скрипты `scripts/` — вспомогательная история
исследования, не нужны для запуска финального решения. Квантизация в финальном
обучении и инференсе **не используется**.

зафиксирована в `final_config.json` и метаданных весов. Выбор лучшей эпохи и
калибровка используют ту же валидацию, поэтому независимый F1 может быть ниже.

побитово. Повторный инференс в локальном окружении дал те же 6600 меток.
